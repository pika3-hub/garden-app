# Hermes とのチャット画面 設計

2026-10-30 にユーザーと決めた設計。段階5 の続き（作業2「Hermes に聞くパネル」は PR #96 で本番反映済み。`2026-10-29-hermes-ask-panel-design.md`）。wishlist の「一覧からの自由な会話（PC 版 Element X のようなチャット）」にあたる。

## 目的と背景

ユーザーはアプリを主に **PC** で使う（スマホは写真のアップロード用）。パネルは植え付け・作物・品種の詳細画面にしか無いので、**まだ登録していない野菜**について相談したいとき（育て方、いつ栽培するか）に開く場所が無い。Element X は手数が多いので使いたくない。

相談の流れで「作物として登録して」のように、そのまま Hermes に登録させたい。頼めることに制限はない（作物に限らず、タスク・日記なども）。

## 決まったこと（ユーザーが決めた）

- **チャット専用の画面**を作る（モック案A: Element X の PC 版のように、左に会話の一覧、右に選んだ会話の中身）。今の会話の履歴（`/conversations/`）とは別の画面で、履歴の画面は今のまま残す
- 会話は**複数**持てる。別の話題を並行して続けることがある。「＋ 新しい会話」で始め、一覧で前の会話を選べば続きから話せる
- Hermes にできることは**絞らない**（パネル・Element X と同じ道具。登録も頼める）
- **パネルでした会話（植え付け・作物・品種の画面の会話）も、左の一覧に並べて続きを話せる**
- 入口: ナビの「Hermes」はそのまま。今ある Hermes の画面のタブ（`_hermes_tabs.html` の「会話」「アドバイス」）の先頭に「チャット」を足す（今のナビにはドロップダウンが無いので、それに合わせた）。**ログイン中はナビの「Hermes」でチャットのタブが開く**。ログアウト中は今どおり「会話」のタブが開き、「チャット」のタブは出ない。チャット画面の URL を直接開いたら、ほかの編集の画面と同じくログインへ案内する（`OWNER_ONLY_GET_ENDPOINTS`）
- 会話の**題名を変えられる**
- 会話を**削除できる**。削除するとチャットの一覧と**会話の履歴の画面（`/conversations/`）の両方から消える**（取り込みでまた現れない）
- **Hermes の中の記録（`state.db`）は今回は消さない**。Hermes の中まで消す手段はいつか作りたい（wishlist に記録）

## Claude が決めたこと（ユーザーは確認していない。違えば直す）

- URL は `/hermes/chat/` など（作る人の判断）。ナビの「Hermes」の行き先をログインの有無で変える（ログイン中はチャット、そうでなければ会話の一覧）。ナビの active 表示はチャット画面でも「Hermes」
- 中身の動き（送る・返事が流れて出る・道具の灰色の1行・承認の「許可する／しない」・答えの下のリンク・履歴は Hermes から直接読む）は**パネルと同じ**。中継（`hermes_ask_routes.py` の runs / events / approval）と `hermes-ask.js` の部品はできるだけ使い回す。パネル用に作った JS を画面用にも使える形に分けるかは作る人の判断
- 自由な会話の Hermes への指示: 対象のデータは無い。「アプリのチャット画面から相談している」「パネルより長めに答えてよい」程度。パネルの会話を一覧から続けるときは、**パネルと同じ対象の指示**（その植え付け・作物・品種を見ている前提）を渡す
- 一覧に並べるもの: `hermes_chats` の行すべて（自由な会話、パネルの会話。パネルで「新しく始める」をして `active=0` になった前の会話も）。新しい順（最後に使った時刻）。パネルの会話には対象の印（「植え付け: 玉ねぎ（ネオアース）」など）。対象のデータが消えた会話は印を「（削除済み）」にして、中身は読めて続きも話せる（自由な会話と同じ扱いの指示にする）
- `active=0` の古いパネルの会話をチャット画面で続けても、パネルで開く会話（active）は変えない
- 題名:
  - 新しい会話は、最初の質問の先頭（30文字ほど）をすぐ題名にする（取り込みの 15 分を待たずに一覧に出すため）
  - 題名を変えたら、チャットの一覧と会話の履歴の画面（一覧・詳細）の両方に出る。取り込み（`POST /api/v1/conversations` の upsert）で **Hermes の題名に上書きされない**
  - 変えていない会話は、取り込み後は Hermes が付けた題名を出してよい（どちらを出すかは作る人の判断。変えた題名が常に勝つこと）
- 削除:
  - 対象はアプリの会話（`hermes_chats` にある会話）だけ。Element X の会話は削除できない
  - 削除の前に確認を出す
  - 消すもの: `hermes_chats` の行、`conversations` の行と、それに付く発言・縮小版の写真（`uploads/` のファイルも）・結び付き
  - 消したことを覚えておき、取り込みで同じ Hermes の会話 ID が来ても登録し直さない（同期スクリプトにはエラーにせず成功で返す。同期スクリプトの状態が壊れないように）
  - 残すもの: その会話で保存された「Hermes のアドバイス」、Hermes が登録・変更したデータ（作物・タスクなど）、Hermes の中の記録
  - 走っている途中の会話を消したときは、Hermes の run はそのまま終わらせてよい（結果を捨てるだけ）
  - パネルの active な会話を消したら、そのパネルを次に開いたとき新しい会話が始まる
- 画面の幅: PC が中心。スマホ幅では崩れずに読めれば足りる（左の一覧を上に畳むなど、作る人の判断）
- `hermes-skill/SKILL.md` の「アプリのパネルからの相談」に、チャット画面（対象なし）から来る相談の扱いを書き足す（アドバイスの保存は今の決まりどおり。対象なしならひも付けなし）

## ゴール

1. ログイン中、ナビの「Hermes」でチャットのタブが開く。左に会話の一覧、右に選んだ会話。ログアウト中は今どおり会話の一覧が開き、チャットのタブは無い
2. 「＋ 新しい会話」で質問を送ると、返事が流れて出て、一覧の先頭に最初の質問から作った題名で並ぶ
3. 「オクラを作物として登録して」と頼むと Hermes が登録し、答えの下に作物へのリンクが出る
4. 一覧で前の会話（自由な会話・パネルの会話）を選ぶと、過去のやりとりが出て、続きを話せる
5. 題名を変えると、チャットの一覧と `/conversations/` の両方に新しい題名が出て、取り込みのあとも変わらない
6. 会話を削除すると、チャットの一覧と `/conversations/` から消え、15分後の取り込みのあとも現れない
7. 未ログインではチャット画面を開けない（入口も出ない）

## 対象外（今回やらないこと）

- Hermes の中の記録（`state.db`）の削除（wishlist）
- 写真の添付（wishlist の「パネルからの写真の添付」と一緒に考える）
- Element X の会話をチャット画面で続けること（Matrix の会話は別の経路で、API Server からは 409）
- 他の詳細画面へのパネルの追加（wishlist）

## 守ること

- パネルと同じ守り: 中継は全部ログイン必須・CSRF 照合、`HERMES_API_KEY` を HTML・JS・JSON に出さない、8642 番を LAN に開けない、`innerHTML` に入れるのはサーバーで変換した HTML だけ（`docs/frontend/hermes-ask-panel.md` の「守ること」）
- 新しい CDN は足さない
- DB の変更はマイグレーション（027〜）で、`IF NOT EXISTS` など何度流しても同じ結果になる形にする
- 削除はユーザーの実データを消す操作なので、`WHERE` で1件に絞る（`docs/db-validation-safety.md`）
- 文書を更新する: `app/models/CLAUDE.md`（表の変更）、`app/routes/CLAUDE.md`（URL）、`docs/frontend/`（チャット画面の部品）、`docs/api/README.md`（取り込みの API の振る舞いが変わるなら）、ルートの `CLAUDE.md` の機能概要、`README.md`、wishlist（この行を消し、Hermes の中の削除を足す）

## 作る人へのメモ（コードを読んで分かったこと）

- `hermes_chats.session_id` と `conversations.hermes_id` は同じ値（`conversation_routes.attach_origin` がこれで突き合わせている）。削除はこの値で1件に絞れる。発言・写真・結び付きは `ON DELETE CASCADE` で消えるが、`uploads/conversations/` の縮小版のファイルは自分で消す
- `advices` には会話への参照が無いので、会話を消してもアドバイスは残る
- 圧縮で Hermes の会話 ID が変わった続き（`parent_hermes_id` でつながる子の行）も、削除・題名・「消したことを覚える」の対象に含める。取り込みでは `hermes_id` か `parent_hermes_id` が消した ID に当たれば登録しない
- 今の `HermesChat.get_active(None, None)` は対象なしの active を1つにまとめる。自由な会話は複数持つので、行の id で扱う（active の仕組みはパネルの会話だけに使う）
- 同期スクリプトは成功の返事しか見ないので、取り込みを断るときも 200 と同じ形で返す
- 走っている途中の会話を消すと、`hermes_chats` の行が無いので events・approval は `find_by_run_id` で 404 になり、結果を捨てる動きになる（求めどおり）
